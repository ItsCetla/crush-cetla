Forked from Charm's Crush

The coding agent that only talks to your providers.

Crush's agent, TUI, LSP and MCP support, with the phone-home taken out. No telemetry, no catalog fetches, and the only update check is a GitHub release lookup you can turn off. Web tools stay off until you say so, cloned repos stay inert until you trust them, and your OpenCode setup comes along.

What's different

Same agent. Much shorter list of who it talks to.

Upstream Crush is excellent. This build changes what it does without asking, not how it codes. Every change is listed in the changelog.

No phone-home

PostHog telemetry, Charm's update check, the Catwalk and Hyper catalog fetches, the Hyper vendor service and the forced Termux DNS resolvers are removed, not just disabled. The provider catalog is a local file you refresh on purpose with tada update-providers.

Web tools off by default

fetch, agentic_fetch, download and sourcegraph are hidden from the model until you run option web-tools true. Even then, every request asks first. Downloads are capped and headers are redacted in logs.

Untrusted projects stay inert

A cloned repo's tada.json, tadarc and OpenCode config are ignored until you run tada trust. No MCP servers or LSPs start from a project you have not vouched for. .env files are no longer auto-loaded.

Stricter bash auto-approval

Only a single, parsed, read-only command runs without a prompt. Wrappers such as env and timeout, redirections, pipes into writes and multi-line commands always ask.

Manual, Plan, Edits or Auto

shift+tab cycles four permission modes, always shown in the status bar. Manual asks before edits and commands, Plan talks it through before any code, Edits approves file edits inside the project and asks for the rest, and Auto skips prompts while system level commands stay blocked. Every prompt says what kind of action it is, deletes always ask, and ctrl+q takes back control from any screen.

Claude Code inside Ta-Da

Have the claude CLI? Pick Claude Code in the model picker and Ta-Da runs your own claude each turn, with its edits shown as Ta-Da diffs, its tool calls going through Ta-Da's permission prompts and its questions in Ta-Da's dialog. Ta-Da never touches your Claude login.

Your other computers, put to work

Got an M1 with room for 4 agents and a 3060 Ti with room for 2? Add them with machine add in tadarc, tada machines add, or just tell the AI. It hands them side work in parallel, falls back to your main model when one drops, and tada machines shows which are online and how many slots are free.

Cockpit, budgets and missions

ctrl+\ opens a cockpit with spend, every action and who approved it, and missions: goals with a checklist that outlive a session. options.budget sets daily, monthly and per-session dollar limits; hitting one asks before the next model call. tada status prints it all once.

Artifacts, kept local

The agent can publish reports, charts, dashboards, small tools, documents and slide decks to a viewer on 127.0.0.1, with versions, comments and a per-page database. Pages make no outside requests unless you allow CDNs. tada artifacts mcp offers the same tools to Claude Desktop.

Magic Context, opt-in

A Go port of cortexkit/magic-context. A background historian compresses old turns before the window fills, the agent can drop stale tool output, and project memory and notes carry over between sessions. All local; turn it on with options.magic_context.enabled.

OpenCode import

MCP servers, providers, model choices, the models.dev cache, rules, skills, custom commands, tool toggles and file-edit permissions come from your OpenCode install. Read from disk only. How it works.

Reviewable releases

Every tag builds six archives and two Windows installers in a public GitHub Actions run with pinned actions, ships a SHA256SUMS.txt, and lands as a draft release that is reviewed before it is published.

Updates when you say so

tada update fetches the newest release, checks it against SHA256SUMS.txt and swaps the binary in place. Ta-Da mentions a new version once; it never downloads on its own, and the check can be turned off.

Its own look

A warm "cetla" theme, a Ta-Da wordmark and a short startup flourish (any key skips it; TADA_NO_INTRO=1 turns it off). Charm's themes are still in the picker.

New in 0.3.0

Tables, charts and tabs in the terminal.

Replies are easier to read without leaving the terminal. Everything is drawn locally from the reply's own text; nothing is fetched.

  • Markdown tables become bordered tables with numbers lined up on the decimal point. Too wide for the window, they shrink text columns first and never cut a number.
  • ```chart blocks draw as bar, horizontal bar, line or sparkline charts in the theme's colours. A broken chart shows its source and the reason.
  • Session tabs: sessions you open stay above the chat, with a + to start another. Click one or press alt+1…alt+9, ctrl+pgdown and ctrl+pgup step through them, and alt+w closes one.
  • Diffs from edits wrap long lines instead of cutting them off.

Copying a reply still gives you the original markdown. Turn the drawing off with options.tui.rich_blocks: false or TADA_NO_RICH=1.

OpenCode import

Already set up OpenCode? You're done.

Ta-Da reads ~/.config/opencode at startup and brings the useful parts across. Nothing is copied or rewritten, and nothing of OpenCode's runs. Plugins in particular are never executed: they are listed in the report so you know what is being skipped.

  • MCP servers, providers and your default and small model
  • The cached models.dev catalog, for providers Ta-Da doesn't already know
  • Rules, global AGENTS.md, skills and custom commands (as opencode:<name>)
  • Tool toggles, deny rules, and edit: allow as a no-prompt list inside the project
  • A network: note for MCP commands like npx -y that reach the registry on every start

Each part has an on/off switch under options.opencode, and TADA_DISABLE_OPENCODE=1 turns the whole thing off. Run tada opencode to see exactly what was read and what was skipped.

tada opencode

What it connects to

Everything that can open a socket, on one list.

Verified with a process-tree connection watcher during the fork's audit, and again on a Windows PC against a local llama-server. If a line isn't here, Ta-Da doesn't do it.

  • Model providers you configure. Chat completions, plus a GET /models discovery call against the same base URL.
  • Machines you add. The same chat and GET /models calls to the URL you gave each machine, which receives the prompts and files the AI sends it.
  • MCP servers you configure. Local processes, HTTP or SSE endpoints, and their OAuth flows if they use one.
  • OAuth refresh for accounts you signed in with tada login.
  • Your claude CLI, only when you pick a Claude Code model. Ta-Da starts the CLI on your machine; the CLI talks to Anthropic itself.
  • Magic Context embeddings, only if you set an endpoint. Its historian and memory otherwise use the model providers above.
  • Artifact pages, only if you allow CDNs. With options.artifacts.allow_cdn, pages may load pinned scripts from a few CDNs and fonts from Google Fonts. Otherwise they are blocked from every outside request. The viewer listens on 127.0.0.1 only and needs a per-machine key, so other programs and web pages can't read your artifacts.
  • Web tools, only once enabled and only after you approve each request.
  • Catalog refresh, only on request with tada update-providers.
  • Update check, unless turned off. At most every 6 hours, one request to api.github.com for this repo's latest release; downloads only when you run tada update. Off with options.update_check: false, option update-check false or TADA_NO_UPDATE_CHECK=1.
  • Nothing else. No telemetry, no crash reports, no other startup fetches.

always, to hosts you chose opt-in or can be turned off

Checking a download

Every release includes SHA256SUMS.txt. Put it next to the archive and compare.

# macOS / Linux
shasum -a 256 -c SHA256SUMS.txt --ignore-missing

# Windows (PowerShell)
Get-FileHash tada_<version>_Windows_x86_64_Setup.exe
Select-String Windows_x86_64_Setup SHA256SUMS.txt

Build from source

Go 1.27 or newer, nothing else. Same command on every platform.

git clone https://github.com/ItsCetla/tada.git
cd tada
go build -o tada .
./tada --version
FAQ

Questions people ask.

Is this an official Charm release?

No. It is an independent fork of charmbracelet/crush. Charm is not involved and does not support it. Bugs in code that isn't fork-specific belong upstream.

Does it work with local models?

Yes. Any OpenAI- or Anthropic-compatible endpoint works, including llama-server, LM Studio, Ollama and vLLM. Set a provider with a base_url and an API key (or a {file:…} reference in OpenCode config) and pick the model. Timeouts are long enough for a cold 30k-token prompt on a 27B model.

Can I use my Claude subscription?

Through the Claude Code engine, yes. Ta-Da doesn't sign in to Claude or read your login: it runs the claude CLI you already use, and the CLI handles sign-in and billing. Claude Code runs its own tools and compaction in those sessions, so Summarize and Magic Context are off. By default the CLI only uses your saved Claude login; Ta-Da strips API keys, tokens, custom endpoints and Bedrock/Vertex switches from its environment. Set use_api_key: true to keep them, for example to bill ANTHROPIC_API_KEY.

What does tada trust actually gate?

Project-level config, project OpenCode files, project MCP servers and LSPs, and the no-prompt list for edits inside the project. Until a project is trusted, Ta-Da still works in it but uses only your global config. TADA_TRUST_PROJECT=1 trusts the current directory for one run, which is handy for scripts.

Why are the binaries unsigned?

Signing and notarizing cost money and tie a release to a person's certificate. Instead, every build runs in a public GitHub Actions workflow with pinned actions, and the checksums file lets you verify what you got. If you'd rather not trust that, go build takes about a minute.

Can I turn the web tools on?

Yes: option web-tools true inside Ta-Da, options.enable_web_tools: true in config, or TADA_ENABLE_WEB_TOOLS=1. Each fetch still asks for permission, and downloads are size-capped.

How do I update?

Run tada update (add --check to only look, or -y to skip the prompt). It downloads the release for your platform, verifies it against SHA256SUMS.txt and replaces the binary. On Windows with the installer, quit Ta-Da first, or just run the new Setup.exe; it upgrades in place.

I used this fork when it was called Crush. What happens to my setup?

On first run Ta-Da copies ~/.config/crush and ~/.local/share/crush into its own folders and still reads CRUSH_* variables, .crush/skills and .crushignore. Per-project session history in .crush/ isn't moved. The 0.2.0 Windows installer replaces the old crush.exe and its shortcuts.

What license is it under?
